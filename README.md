# Smart Solar Battery Calculator — Django Backend

Production-oriented Django REST Framework backend for the N01 Smart Solar Battery Calculator. It provides public calculation/upload APIs, admin JWT APIs, Swagger/OpenAPI, tariff management, feedback, and an algorithm-adapter layer for the Python reference engine or MATLAB Runtime service.

## 2. Local setup

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_tariffs
python manage.py bootstrap_admin
python manage.py runserver
```

`manage.py` defaults to `config.settings.development`.

Frontend default origin: `http://localhost:3000`.

## 3. URLs

- Swagger: `http://127.0.0.1:8000/api/docs/`
- ReDoc: `http://127.0.0.1:8000/api/redoc/`

Swagger and ReDoc assets are served locally through `drf-spectacular-sidecar`, so they do not depend on a public CDN.

## 4. Static files — how it now works

There are two different directories by design:

- `static/` is for source assets owned by this project.
- `staticfiles/` is generated by `collectstatic` and contains Django admin, Swagger sidecar and project assets for production.

The important settings are:

```python
STATIC_URL = "/static/"
STATIC_ROOT = BASE_DIR / "staticfiles"
STATICFILES_DIRS = [BASE_DIR / "static"]
```

Production uses WhiteNoise with `CompressedManifestStaticFilesStorage`.

Before deploying, run:

```bash
DJANGO_SETTINGS_MODULE=config.settings.production python manage.py collectstatic --noinput
```

Do not use `|| true` after `collectstatic`. A missing static asset should fail the deployment rather than silently publishing a broken admin/Swagger UI.

### Verify static discovery locally

```bash
python scripts/verify_static.py
python manage.py findstatic admin/css/base.css
python manage.py collectstatic --noinput
```

After collection, check that `staticfiles/admin/` and `staticfiles/drf_spectacular_sidecar/` exist.

## 5. Development vs production settings

Development:

```bash
python manage.py runserver
```

or explicitly:

```bash
DJANGO_SETTINGS_MODULE=config.settings.development python manage.py runserver
```

Production:

```bash
export DJANGO_SETTINGS_MODULE=config.settings.production
gunicorn config.wsgi:application --bind 0.0.0.0:8000
```

Production settings require a real `SECRET_KEY`.

## 6. Docker

Development:

```bash
docker compose up --build
```

The production image uses `scripts/entrypoint.sh`, which runs migrations, executes `collectstatic` without suppressing errors, performs `check --deploy`, then starts Gunicorn.

For a production container, provide at minimum:

```env
DJANGO_SETTINGS_MODULE=config.settings.production
SECRET_KEY=<strong-secret>
ALLOWED_HOSTS=api.example.com
CORS_ALLOWED_ORIGINS=https://www.example.com
CSRF_TRUSTED_ORIGINS=https://www.example.com
DATABASE_URL=postgresql://...
```

## 7. Nginx/VPS note

With WhiteNoise, Nginx does not need to serve Django static files separately. Proxy all application traffic to Gunicorn and WhiteNoise will serve `/static/`. This is the simplest configuration for this project.

If you deliberately choose to serve `STATIC_ROOT` from Nginx instead, map `/static/` to the absolute `staticfiles/` directory and keep `collectstatic` in the deployment process.

Uploaded media should not be treated as static. In production, use a persistent volume/object storage if retained media is added later.

## 8. Static-file troubleshooting

If Django admin or Swagger loads without CSS/JS:

```bash
python manage.py collectstatic --noinput --clear
python manage.py findstatic admin/css/base.css
python scripts/verify_static.py
```

Then request directly in the browser:

```text
http://127.0.0.1:8000/static/admin/css/base.css
http://127.0.0.1:8000/static/battery-api.css
```

For production, also check the server logs for WhiteNoise `MissingFileError` or manifest errors. Do not copy admin files manually into `static/`.

## 9. Calculation engine

Set one of:

```env
CALCULATION_ENGINE=reference_python
```

or:

```env
CALCULATION_ENGINE=matlab_http
MATLAB_ENGINE_URL=http://matlab-service:8081/calculate
```

The public API contract is independent of the selected engine.

## 10. Security reminder

The development bootstrap password `admin / 123` is suitable only for a local demonstration. Never deploy it to an internet-accessible server.

## 11. VPS deployment examples

The `deploy/` folder contains two Nginx patterns and a systemd service example:

- `nginx-whitenoise.conf.example`: recommended simple setup; Nginx proxies everything and WhiteNoise serves `/static/`.
- `nginx-static-alias.conf.example`: optional setup where Nginx directly serves `staticfiles/`.
- `smart-battery-api.service.example`: runs migrations and `collectstatic` before starting Gunicorn.

For your Hostinger VPS, the WhiteNoise proxy configuration is the simplest starting point because there is only one application upstream to maintain.
